## Acceptance mapping

1. **Unsupported configuration:** real ESPHome validator accepts the proven format and rejects 13 incompatible field/value combinations: internal ADC, PDM, 16/44.1/96 kHz, 8/16/24-bit, left/right/mono, primary clock mode and DC correction. Firmware generation/compilation exercises schema integration.
2. **Signed decode and safety:** production `decode_s32le` and `magnitude_s32le` execute with `INT32_MIN`, `INT32_MAX`, -1, zero and mixed words under ASan/UBSan. Unsigned assembly avoids signed shifts; wider negation gives the valid `2147483648` magnitude. YAML `mic_diag` uses that tested function.
3. **Count/channel/duration:** retained fixture contains 12 stereo input frames and four independently specified expected frames. Every fixed read chunk size 1..96 bytes produces exact output. A one-second fixture repetition yields 16000 stereo frames. The independent smoke uses a different ramp and varying 1..4096-byte reads. Ch0/ch1 order and 32-bit words remain unchanged; wake's channel-1 selector is unchanged.
4. **Existing behavior:** capture/follow-up and response-state real-header harnesses plus bridge upload/response-pacing and Home session tests exercise the preserved software paths. No FIR/model/pacing/admission change. The intentional correction is retaining phase/trailing frames across reads instead of silently dropping them per read. Physical wake/VAD/upload/audible-playback regression is **open**.
5. **Repeatability:** repository retains `tests/firmware/respeaker_pcm_fixture.json`, `tests/test_respeaker_pcm.py` and the production header. Native tests and firmware compiles require no Hermes endpoint or real audio.
