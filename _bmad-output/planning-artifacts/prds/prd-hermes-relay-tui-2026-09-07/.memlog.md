- (decision) Scope the PRD to a private household pilot; calibrate rigor toward one real home deployment rather than public launch or commercial distribution.
- (decision) Use the coaching path with a journey-led entry: named household sessions first, then capabilities and globally numbered requirements.
- (change) UJ-1 delivers the dinner answer multimodally: the room display renders Missy’s response text while the puck speaks the same response aloud.
- (decision) When the Hermes path is unavailable, the display shows a disconnected state and the puck shows a local visual unavailable indicator; the device never presents a local response as Missy.
- (open-question) Decide whether the puck should add a fixed local spoken status phrase while disconnected; this would be device-authored status, not a Hermes/Missy response.
- (decision) Disconnected behavior is visual-only in v1: displays show the disconnected state and the puck shows a local indicator; no fixed spoken fallback phrase is played.
- (decision) UJ-2 setup uses iOS Settings: Add opens a discovery list, selecting the puck shows a connecting state, and successful pairing produces success indicators on both iOS and the puck before room/profile configuration.
- (acceptance) Enrollment journey acceptance: a discovered puck appears in iOS, selection shows connecting feedback, success is visible on both surfaces, and the device remains inert until explicit approval plus room and wake-word/profile configuration.
- (decision) After successful device connection, iOS immediately enters guided setup for room assignment and wake-word/profile mappings; it does not return the user to an unconfigured device list.
- (decision) Guided device setup is ordered room first, then one or more wake-word/profile mappings, then a final ready confirmation.
- (decision) UJ-3 presents a puck detail screen with a Disconnect action; Disconnect revokes the device credential and Hermes access, not merely the current socket, and leaves the powered puck visually disconnected until re-enrollment.
- (acceptance) Revocation journey acceptance: disconnecting an approved puck from iOS immediately prevents wake, capture, and Hermes submission while powered; the device requires explicit re-enrollment to return.
- (decision) Disconnect requires an explicit iOS confirmation explaining that the puck will stop working until re-enrolled; only confirmation revokes its device access.
- (decision) UJ-4 departure cards replace ambient photos on every display at the effective threshold and show event name, location, calculated departure time, and a countdown; cards recompute on changes, clear on cancellation or event start, and remain visual-only.
- (acceptance) Calendar journey acceptance: a qualifying event promotes the same actionable card across displays, updates or clears from calendar changes, and returns all displays to ambient photos at event start.
- (decision) UJ-5 iOS is a full voice doorway: tap to speak shows listening, thinking, and speaking indicators; Amanda hears Missy’s response and sees the transcript, which remains in iOS local history.
- (change) Narrow UJ-6 to the validated TUI role: another direct voice-chat gateway to Missy. Diagnostic detail remains an engineering capability, not a confirmed household journey.
- (decision) During UJ-1 capture, the room display shows live transcription as words arrive while the listening state remains visible until capture ends.
- (change) Drafted the journey-led PRD spine from confirmed discovery: six journeys, FR-1 through FR-21, cross-cutting NFRs, guardrails, MVP scope, metrics, and open questions.
- (decision) Missy response text streams onto the room Display as the voice response arrives, then remains visible as the completed answer while speaking finishes.
- (decision) Hermes clarification and approval prompts are mirrored as visible prompt text/state on the room Display, but responses remain voice-only in v1; Display touch cannot create, submit, or resume a prompt response.
- (decision) Set the v1 post-response follow-up window to eight seconds; after it expires the Puck returns to Wake Mapping detection, while exact stop remains a silent local close.
- (decision) Keep detailed diagnostics out of the MVP household experience. The TUI remains a voice-chat doorway; diagnostic detail is an engineering capability used when needed, not a household journey or acceptance target.
