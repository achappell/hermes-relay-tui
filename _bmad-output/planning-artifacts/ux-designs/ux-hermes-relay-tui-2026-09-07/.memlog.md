- (event) Amanda confirmed that all candidate upstream brief, addendum, PRD, reconciliation notes, and review rubric files apply to this UX pass.
- (decision) Trust boundary: Amanda would lose trust immediately if the wrong Hermes profile answered.
- (decision) Primary UX moment: the conversational back-and-forth matters most; even if the right answer does not arrive first, the follow-up must feel natural.
- (decision) Desired outcome: After the dinner answer, Amanda should feel informed because she received everything needed to start dinner and know when.
- (decision) Scope boundary: Hermes owns answer content, wording, correctness, and domain context. This UX pass owns the doorway experience: profile routing, turn-taking, state feedback, presentation, privacy, and recovery. Informed/ready is a user outcome, not a content specification.
- (decision) Follow-up opening: the bounded follow-up window should play a sound cue indicating listening has resumed and show a listening state.
- (decision) Profile identity: the active Hermes profile should be shown in the response.
- (decision) Follow-up closing: when the bounded follow-up window ends without new speech, provide a closing cue.
- (decision) Unavailable profile feedback: provide a local sound and visible status while failing closed; do not capture, submit, or fall back to another profile.
- (decision) Connection-loss recovery: provide an explicit retry action after a dropped connection during a turn.
- (decision) Shared feedback personality: clear, fun, and friendly across the puck, displays, iOS, and TUI.
- (decision) Profile identity presentation: show the active profile on the room display and in the iOS/TUI header; do not speak the profile name through the puck.
- (decision) Ambient presence: when idle, the room display should remain in the background rather than demanding attention.
- (decision) Playfulness placement: the clear, fun, friendly quality should live in the display presentation, including the puck\u0027s tiny status-display presentation.
- (decision) Retry behavior: Retry reconnects only; it never replays the interrupted turn. The unresolved turn remains visible and a fresh wake or explicit new prompt is required.
- (decision) Active display motion: show an animation while connecting and make the response feel present through animation synchronized with the voice while it speaks. Keep this active-state presentation distinct from idle ambience.
- (decision) Audience: children using shared household devices are a first-class UX consideration for the pilot.
- (decision) Children may use shared puck and display for ordinary wake, conversation, and follow-up; device setup, profile mapping, and administration remain on iOS.
- (decision) Shared-device history: puck and displays retain no conversation history; intentional Local History remains on iOS and the TUI.
- (decision) Child-readable active states: shared displays must make all core phases understandable—heard, listening, working, speaking, unavailable, and stopped—with readable text; animation is welcome, and sound cues support rather than replace visual meaning.
- (decision) Reduced motion: replace active animation with a static state and readable text; sound cues remain available.
- (decision) Audio failure presentation: if Hermes text completes but response audio fails, show the text as complete with an unavailable-audio status; do not present a false speaking state.
- (decision) Surface scope: exclude Photon from the first-release UX pass because it is not defined in the brief or PRD surface list.
- (decision) Visual direction narrowing: reject Sunlit Storybook and Comic Stage. Night Console is the preferred base. Quiet Gallery is acceptable in principle but too bright; any retained qualities must be adapted to a darker treatment.
- (decision) Visual density: retain Night Console\u0027s instrument-panel density; preserve high contrast and use readable state labels and animation for child and room-distance comprehension.
- (decision) Final state contract: map canonical protocol states to child-readable labels, expose the active Profile before capture, and keep text authoritative over color, motion, and sound.
- (decision) Final recovery contract: iOS and TUI own Retry as reconnect-only; an interrupted turn is unresolved, shared-device text is volatile and cleared at terminal boundaries, and Active Turn outranks a Departure Card only on its selected Room Display.
- (event) Key-screen mocks rendered for room active turn, iOS setup, and client recovery; visual QA is limited to offline source inspection because browser policy blocks new local-file tabs.
- (event) UX workflow finalized: DESIGN.md and EXPERIENCE.md are final, validation report and reviewer follow-up evidence are complete, and promoted key screens cover room active turn, iOS setup, and Client recovery.
- (decision) Finalization boundary: remaining proximity, credential, Media Server, Immich, calendar, kiosk, localization, macOS, and cue-duration questions are explicitly downstream or future-scope and non-blocking; the locked UX contract remains final.
- (decision) Scope boundary applied to key screens: mocks show where Hermes response text appears but do not invent answer wording; the dinner prompt is the user's request, not a UX-authored response.
- (event) Handoff complete: final UX spines, reconciliations, review evidence, validation twins, chosen Night Console reference, and promoted key screens are ready for downstream architecture and stories.
