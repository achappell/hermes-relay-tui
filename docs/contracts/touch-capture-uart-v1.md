# Touch capture UART v1 — proposed 1-E-1 implementation contract

Status: draft, reviewed with the 1-E-1 specification. This local peripheral protocol carries capture only; it creates no Home identity or authorization. Product limits come from STD-7 and the selected hardware note. Exact framing and deadlines below are proposed engineering choices, not previously deployed behavior.

## Hardware and sampling

Use 921600 baud, 8N1, no hardware flow control: S3 TX43 → C6 RX19, S3 RX44 ← C6 TX18. S3 GPIO6 drives C6 reset open-drain: release by default, pulse low for 100 ms only during explicit failed-link recovery. GPIO43/44 must carry no application console output; select USB console and document the board switch. Define EXIO5 as USB_SEL and initialize it low, preserving that bit through LCD/touch expander writes; the current all-high initialization selects CAN. Verify native USB remains reachable throughout startup. Any boot noise is discarded before the version handshake.

C6 I²S standard Philips RX uses BCLK0, WS1, DIN2; microphone L/R is low (left slot). Capture at 16000 frames/s with two 32-bit wire slots; extract the signed microphone sample from the left slot and convert its 24 significant bits to signed-16 little-endian without gain or wraparound. Confirm alignment with the INMP441 datasheet and fixture vectors before implementing conversion. GPIO3 is reserved for future amplifier output; hold amplifier DIN low so shared capture clocks cannot clock floating data into the connected amplifier. Playback is not initialized here. Capture clocks/DMA remain off outside an authorized capture. Discard startup samples before STARTED: at 64 clocks/frame × 16 kHz, initial 2^18-clock settling is 256 ms and standby 2^14-clock settling is 16 ms. Use the initial allowance whenever the prior power state is unknown; check conversion with signed endpoint fixtures and bench data.

Reference: [Espressif ESP-IDF 5.3.3 C6 I²S](https://docs.espressif.com/projects/esp-idf/en/v5.3.3/esp32c6/api-reference/peripherals/i2s.html), [INMP441 datasheet](https://invensense.tdk.com/wp-content/uploads/2015/02/INMP441.pdf), and [Waveshare 7B documentation](https://docs.waveshare.com/ESP32-S3-Touch-LCD-7B). The Private Vault hardware/wiring notes own the selected board pin allocation.

## Framing

Encode each frame with COBS and terminate with zero. Decoded bytes are: version u8 (=1), type u8, payload length u16, link generation u32, capture number u32, sequence u32, payload, CRC32 u32. All multibyte integers are little-endian. CRC is IEEE CRC-32 over header and payload; the standard `123456789` check value is `0xcbf43926`. Payload ≤1024 bytes, decoded frame ≤1044 bytes, encoded frame including delimiter ≤1050 bytes. Reject larger declarations before copying; use fixed-capacity buffers.

| Type | Direction | Payload / meaning |
|---|---|---|
| 1 HELLO | S3 → C6 | Empty; proposes fresh nonzero link generation while idle. |
| 2 READY | C6 → S3 | Empty; echoes generation, microphone disabled. |
| 3 START | S3 → C6 | Empty; new nonzero capture number, only after Home readiness. |
| 4 STARTED | C6 → S3 | Empty; I²S startup succeeded, precedes all PCM. |
| 5 PCM | C6 → S3 | 1–512 signed-16 samples, consecutive sequence from zero. |
| 6 END | S3 → C6 | Empty; stop sampling and drain already accepted PCM. |
| 7 ENDED | C6 → S3 | u32 total PCM bytes; sequence is the next PCM sequence. |
| 8 ABORT | Either | u8 reason; discard pending capture immediately. |
| 9 KEEPALIVE | S3 → C6 | Empty; renew current capture lease. |
| 10 ERROR | C6 → S3 | u8 reason; capture disabled. |

Reason codes: 1 cancelled, 2 timeout, 3 malformed, 4 overflow, 5 I²S failure, 6 transport lost, 7 busy. HELLO/READY use capture zero; non-PCM controls use sequence zero except ENDED. All active messages must match link generation and capture. Generate a fresh link generation on connection/recovery, increment capture number per tap, and establish a new link before counter reuse. The host capture ID combines the WebSocket connection generation and capture number; it is opaque, unique within that connection and ≤64 characters.

The C6 boots unbound with I²S off and accepts START only after a completed HELLO/READY exchange. Within that link generation, START must use a capture number strictly greater than the last accepted START, including after terminal cleanup; delayed duplicates cannot reopen capture. Discard UART buffers during rebind and fence all queued callbacks by generation. The C6 accepts START only while idle. Accept a matching autonomous ENDED while the S3 is still capturing. A matching END arriving after successful ENDED is idempotent: repeat the cached terminal acknowledgement, never restart capture or report a new error; the S3 sends host `mic_end` at most once. Duplicate or mismatched active commands never open/restart I²S. A new HELLO during capture aborts that capture before establishing a new link. Idle parser errors resynchronize at the next delimiter; corruption, missing/duplicate PCM sequence, UART errors or overflow during capture invalidate the whole capture. Do not retransmit PCM. A matching ENDED with exact sequence/byte totals is required before sending host `mic_end`.

## Ordering, memory and deadlines

Initialize Wi-Fi from ignored installation configuration and wait for IP readiness before opening `/state`; network loss invalidates the connection generation. Document `sdkconfig.installation` and the explicit build invocation that layers it over tracked defaults; ignore generated credential-bearing configuration and never log its values. Keep the S3 toolchain unchanged; document an exact ESP-IDF 5.3.3 C6 build environment.

Talk sends schema-1 `mic_start` on the existing `/state` socket. Only a matching `mic_ready` with `capture_terminal: true` enables UART START; absent capability fails closed with an incompatible-host message, not a silent legacy fallback. Use a single C6 UART writer: STARTED precedes PCM and ENDED follows every accepted PCM frame. STARTED causes host `mic_capture_started`; then one sender forwards PCM in order as binary WebSocket messages. Use one ordered sender for controls and PCM. Preserve actions in legacy display mode, but disable prompt-action controls in Touch voice mode: its host currently rejects action frames. Active typed-choice integration remains 2-E-5. Bound each PCM queue to 16 × 1024 bytes; exhaustion or failed/partial writes abort instead of dropping samples. No audio files or raw-audio logs.

Allow 25 seconds for host admission (existing claim and session-open allowances are 10 + 8 seconds). Allow two seconds from host readiness to actual STARTED. Capture auto-finishes by 15 seconds or 480000 bytes, whichever comes first; C6 and S3 enforce both. S3 sends a KEEPALIVE every 250 ms from UART START through STARTING, capturing and finishing/draining; START opens the lease; C6 stops/discards after one second without renewal, including during settling. Cancel during STARTING stops sampling and fences any late STARTED/PCM. UART PCM stall or END acknowledgement timeout is one second. C6's duration/byte bound emits ENDED normally after draining; it does not silently truncate and continue. On an invalid stream, never emit a successful ENDED.

Host adds a 25-second admission deadline, two-second start deadline, and 17-second capture-end watchdog from `mic_capture_started`; the two-second terminal allowance does not expand the 15-second sampled-audio budget. Cancel the capture-end watchdog immediately when valid `mic_end` is accepted, before transcription; it does not limit STT or Home response duration. Host expiry aborts rather than submits partial audio. Deadline tasks must be cancelled and awaited on completion/close, with generation checks suppressing late grants. Cancellation while admission is pending closes the socket, ensuring serialized host ingress cannot later activate the cancelled capture. Later taps require a newly established connection.

Cancel is available while awaiting admission, starting or recording; accepting Finish atomically disables Finish/Cancel and enters draining. After host `mic_end`, submission may already have occurred: show Working and do not promise cancellation or offer another Talk until a matching `mic_terminal`. Never derive capture ownership from display snapshot state. Late queued UI commands and UART terminal frames are generation/state checked. Cancel during capture stops I²S, discards PCM and sends matching `mic_abort` when possible; stale abort IDs cannot cancel another capture. Any transport loss fences callbacks, clears both directions' queues and requires a fresh tap after recovery. C6 reboot never restores capture. One reset attempt is allowed after a link timeout; failed recovery leaves capture unavailable rather than looping resets.

Response JSON remains the host's authority. On `audio_start`, acknowledge `audio_playback_failed` with matching turn ID and reason `unsupported`, and drain response binary without buffering it. Never report playback started. Existing snapshots retain final transcript, answer text and unavailable-audio status. Host must distinguish audio-only `audio_abort` from `turn_interrupted`: mark unavailable audio and continue text/events until real turn termination. Late playback-failure reports cannot overwrite error/disconnected state with complete. No second WebSocket reader or independent Home session is added.

## Capture completion and latest-state rendering

Extend only the local Touch protocol, keeping `schema: 1`: host `mic_ready` advertises `capture_terminal: true`, and `mic_terminal` contains the matching `capture_id`, `outcome` (`no_turn`, `complete`, or `error`) and a bounded structural `reason` (≤64 characters, no user text). This is not a new Hermes operation or a replacement display snapshot. Each admitted capture emits one terminal message after its capture/turn tasks and deadlines are cleaned up and another start can be accepted. Empty PCM, cancelled/rejected active capture and empty/failed/suppressed transcription end as `no_turn`; only true Home turn termination yields `complete`. Uncertain/error outcomes never imply success. A failure to deliver the terminal control invalidates/closes that connection; the endpoint never retries the old capture. Rejected admission continues to use matching `mic_reject`.

Retain the capture identity through transcription and the turn finalizer. The firmware consumes one matching terminal in every admitted active phase, including STARTING, CAPTURING, DRAINING, Working and awaiting abort completion. Atomically stop C6, clear pending sends and fence late STARTED/ENDED; never send `mic_end` after terminal. Stale/duplicate terminals have no effect. A matching error requires connection reset before a fresh tap. Cancel clears local audio immediately but another Talk waits for terminal acknowledgement or a fresh connection. After a pre-capture local error, close/rebind rather than waiting indefinitely for an acknowledgement to an unaccepted capture.

Snapshots are current state, not a lossless event log. In `shared/display/display_rules.c`, accept a schema-valid forward-sequence snapshot across a sequence gap even when intermediate phase transitions were coalesced; retain stale/duplicate rejection, prompt validation and contiguous-sequence transition checks. A new connection explicitly resets the reducer generation; old-socket callbacks cannot enter it. Do not synthesize skipped Listening/Speaking phases. Test actual one-slot publisher output through the C reducer: error→coalesced idle→heard and listening→coalesced thinking→complete must paint correctly, without permitting an old snapshot to unlock Talk.

The local socket is not panel authentication: absent Origin is accepted and the configured host Device identity is reused. The bench/deployment guide must require an isolated trusted S3↔host network and document listener/firewall restriction; a shared/untrusted LAN is not a passing authorization setup. No Home credential is moved to the S3. This slice does not add public remote access.

## Verification vectors

Exercise all byte split points, concatenated frames, COBS delimiter loss, invalid lengths/CRC/version, stale generations, duplicate START/PCM/ENDED, missing PCM, exact/over byte budget, positive/negative conversion vectors, lease expiry during startup/drain, stale START after terminal cleanup, cancel during admission/STARTING, empty/failed STT, old terminal controls, early terminal during STARTING/CAPTURING, coalesced snapshots, audio fallback followed by final text, and close during STARTED. Use a deterministic clock; assert I²S start cannot precede readiness and no failure reaches host `mic_end`. Bench results must independently prove pin routing, microphone alignment, reset behavior and actual UART throughput under LCD/Wi-Fi load.
